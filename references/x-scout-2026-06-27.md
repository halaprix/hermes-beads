# Solidity AI Security X/Grok Scout — 2026-06-27

## Scope

This scout closes the research gate for `hb-0pn`: use bounded Grok/X-style discovery to identify current AI-assisted Solidity security tools and convert the result into implementation work for a `solidity-dev` agent skill.

## Method

- Direct Hermes `x_search` was not available in this session.
- A broad researcher subagent timed out after 600s with no final summary.
- Grok Build CLI attempted a live/X scout but returned a cancelled empty result after trying to invoke X search internally.
- Bounded fallback used web search constrained to `site:x.com` plus public docs/repositories.
- X posts are treated as discovery signals only. They are not security evidence.

## Decision

Build a Hermes skill first: `solidity-ai-security`.

Do **not** build a dashboard/plugin first. The useful product is a reproducible scan workflow and normalized findings. A UI is justified only after report artifacts and finding fingerprints exist.

## Tool-selection criteria for the Hermes skill

| Criterion | Required for MVP? | Notes |
|---|---:|---|
| CLI support | yes | Agent must run non-interactively. |
| JSON/SARIF/Markdown output | yes | Needed for normalization and report generation. |
| Foundry/Hardhat support | yes | Solidity-dev workflow must fit normal repos. |
| No required SaaS auth | yes | MVP must run offline/local when possible. |
| AI reasoning value | yes | AI should triage, not replace deterministic scans. |
| False-positive control | yes | Use FP-check prompts and validation tests. |
| Historical findings lookup | optional | Solodit/local corpus can improve context. |
| MCP support | optional | Nice for agent UX, not required. |
| Dashboard/UI | no | Defer until scan artifacts stabilize. |

## MVP recommendation

Implement `solidity-ai-security` as a Hermes skill with scripts:

```text
skills/smart-contracts/solidity-ai-security/
├── SKILL.md
├── scripts/
│   ├── run_solidity_security_scan.py
│   ├── normalize_findings.py
│   ├── solodit_lookup.py
│   └── render_report.py
├── templates/
│   ├── audit-report.md
│   ├── grok-x-scout-prompt.md
│   ├── false-positive-triage-prompt.md
│   └── invariant-suggestion-prompt.md
└── references/
    ├── tool-matrix.md
    ├── finding-taxonomy.md
    ├── x-scout-2026-06-27.md
    └── evmbench-validation.md
```

### Minimum workflow

```bash
forge build
forge test -vvv
slither . --json reports/slither.json || true
aderyn --output reports/aderyn.md --format markdown || true
aderyn --output reports/aderyn.json --format json || true
semgrep --config p/smart-contracts --sarif --output reports/semgrep.sarif . || true
```

Then normalize findings, dedupe by fingerprint, run AI triage, and generate:

- `reports/solidity-ai-security/report.md`
- `reports/solidity-ai-security/findings.json`
- `reports/solidity-ai-security/tool-runs.json`

## Guardrails

- Do not auto-apply contract patches that touch funds.
- Do not run live-network exploit attempts.
- Use local Anvil/fork environments only when explicitly scoped.
- Treat X/Twitter as discovery, not evidence.
- Every confirmed finding needs source lines, attacker capability, violated invariant, impact, remediation, and a validation test or explicit reason a test cannot be written.
